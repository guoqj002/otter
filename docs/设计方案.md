## 1. 产品定位

### 1.1 一句话定位

**一只帮你管住「坚持、花钱、投资」的水獭管家 —— 离线可用、无需注册、数据只在本机。**

### 1.2 从 v1 到 v2 的定位变化

| 阶段 | 定位 | 说明 |
|---|---|---|
| v1.0 | 健身习惯打卡器 | 单一场景，v1 只有 今日 / 统计 / 我的 三个 Tab |
| v2.0 ~ v2.2 | 习惯 + 记账 | 用户需要一个入口看清「练了没、花了多少」 |
| v2.3 ~ v2.4 | 习惯 + 记账 + 理财 | 增加股票/基金/ETF/期货盈亏，形成个人财务闭环；并补上密码/指纹保护 |

### 1.3 核心闭环

```
创建习惯 → 今日打卡 → 看连续天数/热力图 ─┐
                                          ├→ 统计页一眼看全：坚持 + 收支 + 盈亏
记一笔支出/收入 → 分类 + 日/月/年报表 ────┤
记一笔理财盈亏 → 柱状/折线/日历回看 ──────┘
```

### 1.4 明确不做

账号体系、云同步、社交/排行榜、训练课程内容、可穿戴接入、付费墙、广告、任何统计 SDK。
**App 不申请 `INTERNET` 权限**，这是产品卖点而不是遗漏。

### 3.5 连续天数（Streak）规则 —— 已实现

1. 以 **本地时区自然日** 为准；落库存 `local_date` + UTC 毫秒双份，避免跨时区错位。
2. `currentStreak` = 从今天（或昨天）向前连续满足频率要求的单位数。
3. 频率非「每天」时按 **周** 计：连续 N 周达成周目标 → streak = N 周。
4. 今天尚未打卡时 streak 显示昨天的值（**不显示 0**），今天打卡则 +1。
5. 断卡 → `current` 归零，`longest` 保留历史最高值。
6. 「指定星期几」频率下，非应打卡日既不累计也不中断。

## 4. 技术方案

### 4.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Flutter 3.47 / Dart 3.13 | 单代码库 |
| 状态管理 | flutter_riverpod 2.6 | 编译期安全、无 BuildContext 依赖、易测试 |
| 数据库 | Drift 2 + sqlite3_flutter_libs | 类型安全 DSL、可写复合 SQL、支持迁移 |
| 路由 | go_router 14 | ShellRoute 承载 5 Tab，详情页走根导航 |
| 通知 | flutter_local_notifications + timezone | 精确闹钟 + 开机重排 |
| 生物识别 | local_auth 3 | 系统指纹，App 不接触生物数据 |
| 摘要 | crypto（SHA-256 × 12000 轮 + 随机盐） | 密码不落明文 |
| 文件 | share_plus / file_picker / path_provider | 导出分享、导入选择 |
| 偏好 | shared_preferences | 主题、昵称、补卡开关、锁设置 |
| 图表 | **CustomPainter 自绘** | 饼图/双向柱/折线/热力图/日历，零图表依赖 |

### 4.2 分层架构（实际目录）

```
lib/
├── main.dart / app.dart            # 入口；LockGate 包在 MaterialApp.builder 上
├── core/                           # theme / router / utils / notification
├── domain/entities/                # 纯数据模型，无 Flutter 依赖
├── model/                          # 数据层：db(Drift) / dao / repositories / mappers
├── application/
│   ├── providers/                  # data / settings / expense / invest / lock
│   └── services/                   # streak_calculator / backup_service / lock_service
└── presentation/                   # 页面与组件
```

**铁律**：`domain` 不 import Flutter / Drift；`presentation` 不直接操作 DAO，统一走 provider。

### 4.3 数据模型（Drift，schemaVersion 4）

```sql
-- 习惯
CREATE TABLE habits (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  icon_code INTEGER NOT NULL,        -- Unicode 码点作存储键
  color_hex INTEGER NOT NULL,
  type TEXT NOT NULL,                -- check | count | duration
  target_value REAL,
  unit TEXT,
  frequency TEXT NOT NULL,           -- daily | weekly | days
  weekly_target INTEGER NOT NULL DEFAULT 7,
  weekdays_mask INTEGER NOT NULL DEFAULT 127,
  reminder_time TEXT,                -- HH:mm，NULL=不提醒
  sort_order INTEGER NOT NULL DEFAULT 0,
  archived_at INTEGER,               -- NULL=未归档
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

-- 打卡（同习惯同一天唯一）
CREATE TABLE check_ins (
  id TEXT PRIMARY KEY,
  habit_id TEXT NOT NULL REFERENCES habits(id) ON DELETE CASCADE,
  local_date TEXT NOT NULL,          -- YYYY-MM-DD（本地时区）
  done_at INTEGER NOT NULL,          -- epoch ms UTC
  value REAL,
  note TEXT,
  deleted_at INTEGER,                -- 软删除墓碑，为增量同步预留
  UNIQUE (habit_id, local_date)
);

-- 里程碑（庆祝去重）
CREATE TABLE milestones (
  habit_id TEXT NOT NULL,
  kind TEXT NOT NULL,                -- streak_3/7/30/100、total_10/100
  achieved_at INTEGER NOT NULL,
  PRIMARY KEY (habit_id, kind)
);

-- 记账流水（金额存分）
CREATE TABLE expenses (
  id TEXT PRIMARY KEY,
  category TEXT NOT NULL,            -- food…other / salary…otherin
  amount_cents INTEGER NOT NULL,
  type TEXT NOT NULL DEFAULT 'expense',  -- expense | income
  note TEXT,
  local_date TEXT NOT NULL,
  created_at INTEGER NOT NULL
);

-- 理财盈亏（有符号）
CREATE TABLE invest_records (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,                -- stock | fund | etf | futures
  amount_cents INTEGER NOT NULL,     -- 正=盈利，负=亏损
  note TEXT,
  local_date TEXT NOT NULL,
  created_at INTEGER NOT NULL
);
```

**迁移策略**（`MigrationStrategy.onUpgrade`）：

| from | 动作 |
|---|---|
| < 2 | 建 `expenses` 表 |
| < 3 | `expenses` 加 `type` 列（存量默认 `expense`） |
| < 4 | 建 `invest_records` 表 |

`beforeOpen` 执行 `PRAGMA foreign_keys = ON`，保证级联删除生效。

### 4.4 关键交互流程

**打卡（一次点击完成）**

```
HabitCard
├─ check    → 直接打卡 → 触觉反馈 + 缩放动效 + 「已完成 · 连续 N 天」
├─ count    → 弹层输入数量（记忆上次值）→ 确认
└─ duration → 弹层快捷按钮（10/20/30 分钟 / 自定义）→ 确认
已打卡 → 右侧 ✓ + 完成时间；点击弹出菜单（撤销今日打卡 / 查看详情）
触发里程碑 → 全屏庆祝卡片（streak_7 等）
```

**记账 / 理财录入**

```
FAB → 底部弹层
记账：收入/支出 → 分类宫格 → 金额（数字键盘）→ 备注 → 日期 → 保存
理财：类型（股票/基金/ETF/期货）→ 盈利/亏损 → 金额 → 备注 → 日期 → 保存
```

**周期切换（记账 / 理财 / 统计财务概览三处共用同一套逻辑）**

```
periodRange(mode, anchor) → [from, to) 字符串区间，直接用于 SQL 查询
shiftPeriod(mode, anchor, ±1) → 日/月/年各自平移
periodTitle(mode, anchor) → 「2026 年 11 月 5 日 / 2026 年 11 月 / 2026 年」
```

**锁定流程**

```
启动 / 回前台 → LockGate 判断 pinEnabled && (首次 || 离开>30s)
  → 覆盖层显示 LockScreen（水獭头像 + 6 位圆点 + 数字键盘 + 指纹键）
  → 错误：抖动 + 红字提示；正确：淡出，原页面状态完整保留
```

### 4.5 状态管理约定

| Provider | 作用域 | 说明 |
|---|---|---|
| `databaseProvider` | 全局 | 单例 AppDatabase |
| `settingsProvider` | 全局 | 主题、昵称、补卡开关 |
| `expensePeriodModeProvider` / `expenseAnchorProvider` | 记账页 | 页面独立周期，不干扰理财页 |
| `investPeriodModeProvider` / `investAnchorProvider` | 理财页 | 同上 |
| `statsFinanceModeProvider` / `statsFinanceAnchorProvider` | 统计页 | 财务概览专用周期 |
| `lockProvider` | 全局 | 锁状态（locked / pinEnabled / biometricEnabled / autoLock） |

## 6. 安全与隐私

| 项 | 实现 |
|---|---|
| 密码摘要 | 随机盐（16 字节）`+'|'+pin+'|fitstreak'`，SHA-256 迭代 12000 轮；只存 salt + digest |
| 比较 | 常量时间比较，防计时侧信道 |
| 指纹 | `local_auth` 系统弹窗；开启开关前先验证一次；设备无指纹时开关禁用并提示 |
| 自动锁定 | `AppLifecycleState.paused/hidden` 记录时间，`resumed` 时差 ≥30s 触发 |
| 锁屏实现 | 覆盖层 `Stack` 套在 `MaterialApp.builder`，`TickerMode` 暂停动画但不销毁子树 |
| 网络 | 无 `INTERNET` 权限，无第三方统计/广告 SDK |
| 权限清单 | `POST_NOTIFICATIONS`、`SCHEDULE_EXACT_ALARM`、`USE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`、`VIBRATE`、`USE_BIOMETRIC`、`USE_FINGERPRINT` |
| 数据位置 | 应用私有目录 SQLite + SharedPreferences，卸载即清空 |

> Android 侧因 local_auth 要求，`MainActivity` 继承 `FlutterFragmentActivity`。

## 9. 已知限制

1. 数据仅在本机，换机需手动导出/导入 JSON。
2. 提醒依赖系统精确闹钟，国产 ROM 需手动加白名单，否则可能延迟。
3. 密码锁为 6 位纯数字，忘记密码只能清数据重装（当前未做找回）。
4. 理财只记录盈亏金额，不含持仓成本与收益率计算。
5. 仅提供 Android 端，iOS 未适配（依赖 flutter_local_notifications / local_auth 的跨端实现骨架已具备）。
